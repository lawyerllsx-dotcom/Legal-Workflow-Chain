# 接案评估 Skill：委托代理前的案件评估入口

> 定位：五层链的**接案前置总览层**（非平行工作流）——评估 → 报告给决策者 → 按复杂度分流（ad-hoc / 浅链 / 深链）。

## 一、为什么需要接案入口

原工作流缺一个起点：从"拿到一个案子"到"进入五层链"之间没有衔接。没有接案评估，AI 无法判断这个案子该走深链还是单 skill，也不知道该给决策者什么。

接案评估把这件事标准化：**先产出《案件评估报告》给上级/决策者审，再由复杂度决定分析深度。**

## 二、实习 / 执业双模式

skill 内含一个模式开关，两种模式共享核心十步 + 报告结构，一起进化：

| 维度 | 实习模式 | 执业模式 |
|------|---------|---------|
| 报告去向 | 给上级 / 决策者审 | 自己决策 |
| 接/不接结论 | **不带**（上级拍板） | **带建议**（接 / 不接 / 条件接 + 理由） |
| 附加字段 | 「向上级请教的问题」清单 | 「接案红线核验」+ 决策依据 |

**模式切换**：改 skill 的 `模式` 字段，或在调用时明示覆盖。

## 三、报告结构（十步）

1. 案件概要（当事人 / 标的 / 争点一句话）
2. 法律关系定性
3. 证据盘点（已有 / 缺口）
4. 有利因素 / 不利因素（不拍胜诉率）
5. 非诉路径评估（调解 / 协商等）
6. 主要法律依据（调 legal-research）
7. 争议焦点预判（调 dispute-issue）
8. 证据缺口（调 fact-checker）
9. 风险与红线核验
10. **给决策者的建议**：打法选项 2-3 条 + 各自代价 + 待核验清单

> 报告对象 = 上级 / 决策者。结构固定，方便快速决策。实习模式**不带"接/不接"结论**，由上级在报告基础上拍板。

## 四、复杂度分流（接案后）

| 复杂度 | 分流 |
|--------|------|
| 简单 / 模板化 | ad-hoc 单 skill |
| 中等 | 浅链（dispute-issue → legal-research） |
| 复杂 | 五层深链 |

**复杂度三问**：① 核心争点 ≥ 3？② 多被告 / 多法律关系叠加？③ 存在法条竞合 / 司法解释冲突 / 类案分歧？命中任一 → 主动询问是否走深链。

## 五、运行日志进化（反馈闭环）

每次评估跑完自动记一行到运行日志：

```
| 日期 | 模式 | 案子类型 | 标的 | 哪里不顺 / 缺什么 | 上级改了什么 |
```

日志是 skill 进化的数据源：跑真实案子 → 日志喂数据 → 据日志迭代 skill。**不要靠设计者自我感觉，靠真实运行反馈。**
