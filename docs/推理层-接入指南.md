# 推理层 skill 接入指南

> 本项目**不直接分发** `deductive-reasoning` / `dispute-issue-identification` / `conflict-resolution` 三个 skill——它们源自 [THUYRan/Legal-Skills-Chinese](https://github.com/THUYRan/Legal-Skills-Chinese)(CC BY-NC-ND 4.0)。
>
> 本页教你**从原库下载原版 → 按完整协议接线**。按本页接线后,三个 skill 的行为与作者本地版一致。本页只含本项目的**原创协议**(MIT 授权),不含原库 skill 正文。

## 一、为什么不能直接发改好的版本

CC BY-NC-ND 4.0 的 **ND(NoDerivatives)** 条款,对"改编"的精确边界是:

| 行为 | 是否允许 |
|------|---------|
| 个人下载原版、自行修改、本地自用 | ✅ **允许**(ND 明确允许"制作与复制改编版",仅禁止分享) |
| 把修改后的版本**分享/分发**给他人(公开仓库、网盘、群发) | ❌ **禁止**("不得分享改编版") |
| 原样分享原版(不改动) | ✅ 允许(须署名 + 非商用) |

所以正确姿势是:**我们只发方法(协议),不发改好的成品。** 你下载原版,按本页接线,改编版留在自己机器上。

## 二、第一步:下载原版

```bash
git clone https://github.com/THUYRan/Legal-Skills-Chinese.git

# 复制到你的 Claude Code skills 目录(以 Windows 为例)
cp -r Legal-Skills-Chinese/skills/deductive-reasoning ~/.claude/skills/
cp -r Legal-Skills-Chinese/skills/dispute-issue-identification ~/.claude/skills/
cp -r Legal-Skills-Chinese/skills/conflict-resolution ~/.claude/skills/
```

> 原库每个 skill 自带 `SKILL.md`(触发条件 / 能力边界 / 操作步骤 / 输入输出格式 / 法律声明),下载后**不接线也能单独用**。

## 三、第二步:接线成"接力版"(完整协议规范)

按下面清单在原版 `SKILL.md` 上接线。分**通用件**(三个 skill 都要加)和**专件**(各 skill 特有)。

### 通用件(三个 skill 都加)

#### ① 接力模式检测(放 SKILL.md 顶部)

```markdown
### 接力模式检测(所有 skill 通用规则)

加载后静默检查:若上下文存在 `[Skill接力: <本 skill 名>]` → **接力模式**。
- 跳过用户身份询问、新手引导、输出格式选择
- 从上一 skill 的"接力上下文"+"待办"字段直接获取输入
- 聚焦完成待办任务,不主动扩展分析范围
```

#### ② 不触发情况路由排除表

加一张"本 skill 不触发、交给谁"的表,防止误触发抢占:

```markdown
### 不触发情况(强制排除)

| 用户意图 | 应交由 |
|----------|--------|
| 检索法条/案例 | legal-research |
| 核查已有文书事实 | legal-fact-checker |
| 格式化脚注/引注 | legal-citation-comprehensive |
| 编辑 .docx | docx-editing |
| 整理证据到模板 | evidence-catalog-generator |
| <该 skill 之外的推理场景> | <对应 skill> |
```

> 各 skill 的"除外场景"填写:dispute-issue 排检索/核查/格式/演绎/竞合;deductive 排检索/争点/核查/格式/竞合;conflict 排单一法条无竞合/检索/争点/核查/格式。

#### ③ 前置 / 后置接力路由表

列出"输入还缺什么 → 先接力去要"和"本步做完 → 交给谁":

```markdown
### 前置接力(输入不完整时)

| 前置需求 | 接力到 | 说明 |
|----------|--------|------|
| <缺什么> | <skill 名> | 取回后回到本 skill |

### 后置接力(本步完成后)

| 下一步需求 | 接力到 |
|-----------|--------|
| <需要什么> | <skill 名> |
```

#### ④ 接力标记 + 五字段上下文(输出末尾)

```markdown
### 接力标记格式

[Skill接力: next-skill-name]
接力上下文:
- 结论: {一句话核心结论}
- 依据: {关键法条/事实/证据,分条列出}
- 置信度: {高/中/低 + 理由}
- 待核验项: {需下一 skill 或人工核实的点;无则填"无"}
待办: {下一个 skill 需要完成的具体任务}
```

#### ⑤ 接力前自检 + 确认行

输出接力标记前,强制自查三问,通过后输出确认行:

```markdown
### 接力前自检(输出接力标记前强制执行)

□ 接力目标是否正确?
□ "待办"字段是否完整(让下一个 skill 无需重新提取)?
□ 本 skill 的核心任务是否确实已完成?

执行自检通过后输出:`✅ 接力自检通过: 目标正确([skill-name]) | 待办完整 | 本skill任务已完成`
```

### 专件一:dispute-issue-identification

- **后置路由**:识别完成后按需接力——需法条 → `legal-research`;需三段论 → `deductive-reasoning`;涉竞合 → `conflict-resolution`;需写文书 → `legal-fact-checker`
- **深链建议字段**(输出末尾追加一行):

```markdown
### 复杂度判断与深链建议

识别完争点后,按三信号判断是否建议走五层深链:
| 信号 | 触发 |
|------|------|
| 争点数 | 核心争点 ≥3 |
| 法律关系 | 多被告 / 多法律关系叠加(如担保+债务加入+夫妻共同债务) |
| 法源冲突 | 存在法条竞合 / 司法解释冲突 / 类案观点分歧 |

输出末尾追加一行:
- `建议: 五层深链(理由: …)` —— 命中任一信号
- `建议: ad-hoc 单 skill` —— 争点单一、无竞合、模板化
```

### 专件二:deductive-reasoning

- **前置路由**:请求含推理但缺事实 → 先 `[Skill接力: dispute-issue-identification]` 提取争点与事实框架;争点已有但缺法条 → 先 `[Skill接力: legal-research]` 取回法条原文。均需回到本 skill 重跑三段论
- **后置路由**:遇法条竞合 → `conflict-resolution`(解决后回来重跑);推理前提事实存疑 → `legal-fact-checker`;推理链完成 → `legal-citation-comprehensive`
- **前提核验铁律**(大前提法条原文):

```markdown
### 前提核验(法条原文支撑)

大前提 P 的**法条原文必须来自已核验来源**(legal-research / MCP 取回的原文),**禁止凭记忆引用法条编号或原文**:
- P 已有可考来源 → 直接使用,标注条文号
- P 缺失或凭记忆 → **先 `[Skill接力: legal-research]` 取回法条原文**,再回本 skill 重跑
- 任何未核验的法条编号/原文 → 标注 `[待核验]`,不得作为推理前提
```

- **紧密协作对**:`deductive-reasoning ↔ conflict-resolution` 是推理层紧耦合对。遇竞合先跳 conflict,解决后用确定的规范回 deductive 重跑三段论(见专件三)

### 专件三:conflict-resolution

- **后置路由**:冲突已解决 → 接力回 `deductive-reasoning` 用确定规范重跑;冲突依赖的事实存疑 → `legal-fact-checker`。**conflict 是推理链的中途检修站,不是终点**
- **类案检索支撑**(裁决法条竞合/法源冲突时):

```markdown
### 裁决支撑(类案检索)

裁决竞合/法源冲突时,尽量用 MCP 案例检索同类冲突场景的裁判先例(指导性案例/公报案例优先)支撑结论:
- 有权威类案 → 在"依据"字段列出**案号 + 裁判规则**
- 无直接类案 → 标注"无直接类案支撑",裁决依赖学理/规范层级判断,**置信度相应下调**
- 竞合裁决必须给出"适用 X + 排除 Y"的明确结论,不能含糊
```

- **终止接力格式**(冲突无法解决时不强行回 deductive):

```markdown
### 冲突无法解决时的终止条件

| 无法解决的情形 | 处理方式 |
|----------|--------|
| 新一般法与旧特别法冲突(需全国人大常委会裁决) | 标注低置信度,接力到 legal-fact-checker,**不**回 deductive |
| 地方性法规与部门规章冲突(需国务院提出意见) | 同上 |
| 证据势均力敌且无法通过举证责任分配解决 | 标注"需司法鉴定/补充举证",接力到 legal-fact-checker |
| 法律空白且无法通过类推/原则适用 | 标注低置信度,接力到 legal-fact-checker |

[Skill接力: legal-fact-checker]
接力上下文: {冲突无法解决的原因,已标注低置信度}
待办: 仅做最终核查,不需要回推理链——冲突需有权机关裁决/补充证据
```

## 四、第三步:启用编排层(CLAUDE.md)

协议是 skill 内部的事;**让深链真正自动流转**(路由裁决 / F1-F5 监控 / 深链提醒 / relay-log),还需要把编排规则写进你的 `CLAUDE.md`。仓库的 `CLAUDE.md` 模板已含完整编排层,直接照抄即可(见「Skill 路由架构」一节):接力协议五字段 / 接力模式检测 / 路由冲突裁决 / 运行监控 F1-F5 / 深链动态提醒 / 接案评估。

## 五、接线自检

改完跑一遍 [回归测试集](回归测试集.md) 的**用例 1(五层深链)**,检查点:

- 接力上下文五字段逐跳完整传递
- 法条原文已核验,无 `[待核验]` 作演绎前提
- 竞合回环正常(deductive ⟷ conflict 能往返)
- 全程无 F1-F5 故障(上下文断裂 / 接力丢失 / 接力循环 / 结论矛盾 / 错位接力)
