# Skill 回归测试集

> 目的：每次修改 skill（新增 / 瘦身 / 改逻辑）后，跑一遍最小回归集，确认接力衔接不被破坏。**手动跑，非自动化。**

> ⚠️ 本测试集针对**本地完整版**（含推理层三个 skill：`deductive-reasoning` / `dispute-issue-identification` / `conflict-resolution`，本地自用）。这三个 skill 因来源许可（CC BY-NC-ND 4.0）未随公开仓库分发，仅保留在本地 `~/.claude/skills/`。

## 测试用例（3 个典型路径）

### 用例 1：五层深链 🔴 最重

**触发**：用一套完整案件材料跑五层链（接案评估 → dispute-issue → legal-research → deductive ⟷ conflict → fact-checker → citation）。

**检查点**：
- 接案评估报告字段完整（概要 / 定性 / 证据 / 有利不利 / 风险 / 打法 / 建议）
- dispute-issue 输出争点清单 + 深链建议字段
- legal-research 返回法条原文 + 条文号（可核验来源）
- deductive 前提核验（法条原文已核验，无 `[待核验]` 作前提）
- conflict 竞合回环正常（违约金裁决 + 类案支撑）
- 接力上下文五字段（结论 / 依据 / 置信度 / 待核验 / 待办）逐跳完整传递
- 全程无 F1-F5 故障

### 用例 2：ad-hoc 单 skill 🟡 轻

**触发**：用一份简单律师函材料，单 fact-checker 或单 legal-research 出活。

**检查点**：
- 简单任务不走深链（不触发五层）
- 单 skill 正常完成，无多余接力
- 不进 relay-log（可选深链机制下简单任务不记录）

### 用例 3：接案评估入口 🟡 新

**触发**：一个新案子跑接案评估（实习模式）。

**检查点**：
- 自动触发接案评估（工作流规则）
- 报告给上级、不带接/不接结论（实习模式）
- 报告后按复杂度分流建议正确（ad-hoc / 浅链 / 深链）
- 跑完自动记运行日志一行

## 执行纪律

| 改动范围 | 至少跑 |
|---------|--------|
| 任一 relay skill（dispute-issue / legal-research / deductive / conflict / fact-checker / citation） | 用例 1（最深，最易暴露衔接破坏） |
| 接案评估 / 模式开关 | 用例 3 |
| 工具类 skill（docx-editing / evidence-catalog / vision） | 用例 2 |
| 发现故障 → 记 relay-log 故障统计 → 修复后重跑 |
