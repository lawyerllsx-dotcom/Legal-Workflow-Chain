# LegalChain → WorkBuddy 迁移执行与排查报告

> **用途**：把法律 AI 工作流装进腾讯 WorkBuddy 时，按本文一步步执行 + 排查。这份报告是"指挥手册"——给 WorkBuddy 的 AI 读，也给人对照检查。
> **配合**：安装说明.md（阶段 A-G）· 环境配置/01-06 · 使用手册 · 测试与排查指南。

---

## 一、开始迁移：告诉 LLM 的一句话

把**迁移包目录**设为 WorkBuddy 工作目录，说：

> 读 `安装说明.md`，按阶段 A→G 引导我搭建法律工作流环境，包括 Obsidian 和本地 OCR。OCR 按 `环境配置/02` 先选档（默认通用档 V6）。

WorkBuddy 会自动解析安装说明当导师，逐步引导。你要做的：回答它的提问、填 key、点确认。

## 二、迁移全流程（阶段 A-G，每步怎么验 / 怎么排）

### 阶段 A：WorkBuddy 基础
- **验证**：随便问一句能正常回答
- **排查**：装不上 → 检查系统要求（Windows 10+/macOS 10.15+）、网络

### 阶段 B：模型接入（必填）
- **告诉 LLM**：帮我配置 DeepSeek 模型，参考 models.json
- **验证**：模型下拉出现 DeepSeek/GLM、能对话
- **排查**：
  - 模型不出现 → models.json 路径（`~/.codebuddy/models.json` 或 `~/.workbuddy/models.json` 都试）；模型 id 要和平台完全一致
  - 改完不生效 → 重启 WorkBuddy

### 阶段 C：skills + 编排（核心）
- **告诉 LLM**：帮我安装 skills/ 下的技能（官方上传方式），并配置编排规则（项目「指令」或 .workbuddy/memory/MEMORY.md）
- **验证**：① 「已安装」11 个技能都在且启用 ② 问"接案评估怎么触发"→ 能答"复杂度三问分流"
- **排查**：
  - 技能不识别 → 换方式（上传 vs 复制到 skills/ / .agents/skills/ / ~/.workbuddy/skills/）都试，以「已安装」出现为准
  - 编排没生效 → 项目指令贴了吗？MEMORY.md 在工作目录吗？重启

### 阶段 D：MCP 检索
- **告诉 LLM**：按 mcp.json 配置元典和 tavily，key 我自己填
- **验证**：问一个法条返回原文 + 条文号
- **排查**：key 填对了吗 / 网络通吗 / 没配检索源时 AI 标 `[待补]` 属**正常降级**

### 阶段 E：Obsidian 知识库（推荐）
- **告诉 LLM**：读 `环境配置/01` 和 `05-Wiki操作规范.md`，按操作规范建知识库（先 index 和 log，建好分类）
- **验证**：wiki 目录结构建成，`.workbuddy/` 在 vault 根
- **排查**：核心纪律是否传达——先读 index 再回答 / 矛盾标注 / 收纳回 synthesis / raw 只读

### 阶段 F：本地 OCR（可选，两档）
- **告诉 LLM**：按 `环境配置/02` 选档（通用档 V6 默认），装好后适配路径测一个 PDF
- **验证**：`ocr 一个测试.pdf` → 输出同名 `.md`
- **排查**：路径改对了吗（`D:\ai-models` → 本机）/ 依赖装全了吗（requirements.txt）
- **完整档（可选增强）**：按 `06-VL完整档适配指南.md`——**VL 模型引擎首次自动下载**（ModelScope `zhaohb/PaddleOCR-VL-1.5-ov`，约 2.5G），无需手动下

### 阶段 G：验证
- **告诉 LLM**：跑 `测试与排查指南.md` 的 T1-T6
- **验证**：查法条 / 案件评估 / 文书核查三个都能出活
- **排查**：见「快速排查表」

## 三、关键机制备忘（为什么这么配）

| 机制 | 说明 | 作用 |
|------|------|------|
| **编排层** | 项目「指令」字段（所有任务自动继承）+ `.workbuddy/memory/MEMORY.md` | 路由裁决 / 复杂度三问 / F1-F5 / 接案评估自动触发 |
| **skill 触发** | description 匹配（概率性，非确定性）| 触发词写明确才容易命中 |
| **自主规划** | WorkBuddy 深链由**模型自主规划**执行（不是接力标记驱动）| 复杂案件多步自动跑 |
| **workflow-overview** | 多步法律分析先读它了解全貌 | 增强规划确定性 |

## 四、完整档 VL 专项

- VL 模型**引擎自动下载**：`paddleocr_vl_openvino` 首次 VL 触发时从 ModelScope 拉 `zhaohb/PaddleOCR-VL-1.5-ov`（约 2.5G），缓存复用
- 配置：`ocr_contract.py` 的 `VLM_MODEL` / `LAYOUT_MODEL` 设 **None**（自动下载）
- 前提：依赖装全（含 modelscope）+ 网络可到 ModelScope + `MODELSCOPE_CACHE` 可写
- 触发：复杂版式（C 级页 / 低置信行）自动 VL 复验

## 五、快速排查表（迁移中任何问题先查这）

| 症状 | 查什么 |
|------|--------|
| 技能没触发 | 已启用？触发词明确？手动 `/skill名`？|
| 编排没生效 | 项目指令贴了吗？MEMORY.md 在工作目录？重启？|
| 模型不出现 | models.json 路径？模型 id 对平台？重启？|
| 检索不到 | 元典/tavily key？网络？`[待补]` 是正常降级 |
| 深链跳步 | 自主规划遗漏 → 手动提示"先用元典查 585 条再分析" |
| OCR 不跑 | 路径适配？依赖装全？|
| `[VL] Failed` 提示 | 通用档没装 VL 的正常噪音；或加 `--no-vl-crosscheck` |
| VL 下载卡住 | 首次自动下载 2.5G 属正常；确认网络 + MODELSCOPE_CACHE 可写 |
