## 上手操作路径（WorkBuddy 里具体点哪几步）

> 机制之外，先讲清楚在 WorkBuddy 界面里**怎么操作**。核心一句话：**一切都在「项目」里配，一切对话都在「空间」里开**。

1. **新建项目**：WorkBuddy 界面新建一个项目（法律工作流）——它是你的**会话分组**（指令+技能+对话的容器）。
2. **项目内加技能**：项目 → 添加技能 → 上传，把 `skills/` 下的技能逐个加进**项目**（不是只全局上传——项目内添加才保证该项目对话能触发）。
3. **项目内贴指令**：把 MEMORY.md 内容粘贴到项目「指令」字段——这是全局行为规则，项目内所有对话自动继承。
4. **固定文件目录**：把 MEMORY.md 复制为用户级 `~/.workbuddy/MEMORY.md`，写入固定目录规则（材料放 raw/、知识库读写 wiki/）——因为新对话默认在临时目录跑，必须有这条才认准你的工作区。
5. **以后所有对话都在「空间」里开**：在左侧「空间」找到该项目 → 新建对话 → 自动调用项目的指令+技能。**不要在其他地方直接开新对话**（那会脱离项目规则）。

> 详细步骤见 [安装说明.md](安装说明.md) 阶段 A-G；验证走 [测试与排查指南.md](测试与排查指南.md)。

## 关键机制（实测确认）

- **项目 ≠ 工作目录**：WorkBuddy「项目」是会话分组（指令+技能+对话），不是文件读写目录——新对话默认临时时间戳目录。**文件层固定靠用户级 `~/.workbuddy/MEMORY.md`** 固定目录规则。
- **编排层载体**：项目「指令」字段 = 对 AI 的全局行为规则，所有任务自动继承。
- **知识库强制注入 Hook**（核心环节）：用插件化 UserPromptSubmit 钩子每次提问自动注入 wiki 索引，确保"回答前先读 wiki"技术强制——见 [docs/workbuddy-hook-知识库强制注入.md](docs/workbuddy-hook-知识库强制注入.md)。⚠️ WorkBuddy 顶层 hooks 字段被忽略，必须走插件机制。
- **联网内置**：WorkBuddy 原生联网搜索，无需 tavily。
- **GLM 识图**：界面添加 GLM 模型，传图时切换识别（DeepSeek 不支持图片）。
