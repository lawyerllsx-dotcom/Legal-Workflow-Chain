# Legal-Workflow-Chain → WorkBuddy 环境搭建（WorkBuddy 引导式）

> **不用手动一步步做**。你只要把迁移包位置告诉 WorkBuddy，说一句"帮我按这个包搭建环境"，它会读本文件当导师，带你走完全程（含 Obsidian 和本地 OCR）。

---

## 给 WorkBuddy（AI 执行者）的话

你是**环境搭建导师**。用户把迁移包位置告诉你后：

1. **先完整读**：本文件 + `环境配置/` 下三份文档（01 Obsidian / 02 本地 OCR / 03 模型与 Key）
2. **探测环境**：WorkBuddy 是否已装？模型是否已配？技能目录在哪？有没有 Obsidian？
3. **按阶段 A→G 一步步引导**：
   - 能自动做的（复制文件、建目录、写配置骨架）→ **直接做**
   - **凡涉及 API key / 账号 / 密码** → **停下，指导用户自己填**（界面或配置文件），用户自主操作；**key 不发给 LLM、不进对话/日志**；**LLM 绝不接收 key 内容、绝不猜测、绝不自动填**
   - 需要用户手动确认的 → **停下来说明，等用户完成再继续**
4. 每阶段结束确认成功，再进下一阶段
5. 全部完成，引导用户做**阶段 G 验证**

## 给用户（人）的话

打开 WorkBuddy，**新建一个项目**（它就是你的工作区域），然后说一句：

> 帮我按这个包搭建法律工作流环境，包括 Obsidian 和本地 OCR

WorkBuddy 会带着你一步步来。你要做的只是：回答它的问题、填 key、点确认。

## 阶段 A：WorkBuddy 基础
（已装可跳过）
- 下载安装：workbuddy.cn（Windows/macOS）
- 注册登录腾讯账号
- 确认能正常对话

## 阶段 B：模型接入（必填）

- 引导用户去 `环境配置/03` 注册 **DeepSeek**（日常主力；GLM 在 WorkBuddy 界面添加即可，识图时切换用）
- 两种配置方式任选：
  - **界面**：WorkBuddy **设置 → 模型 → 添加模型**，填 `base URL + API key + 模型 id`
  - **配置文件**：把 `models.json` 复制到 `~/.codebuddy/models.json` 或 `~/.workbuddy/models.json`（按你的版本选一个目录），填上 key。官方结构为 `models` 数组，字段 `id/name/vendor/url/apiKey/supportsToolCall/supportsImages`
- 确认：随便问一句能正常回答

## 阶段 C：skills + 编排规则

> ⚠️ **实测 2026-08-06**：WorkBuddy 的运作单位是「**项目**」——项目内有「指令」（行为规则）和「技能」，在左侧「空间」新建对话时，会**自动调用该项目里配好的指令 + 技能**。所以技能和规则都要落在**项目内**，不是全局。
> ⚠️ **项目 ≠ 文件工作目录**（实测 2026-08-07）：WorkBuddy 的「项目」是**会话分组**（指令+技能+对话的容器），**不是文件读写目录**——新对话默认在临时时间戳目录跑。文件层的固定要靠**用户级记忆**（见④）。

**① 新建项目（会话分组）**：WorkBuddy 界面新建一个项目（法律工作流）。后续的指令、技能都配置在这个项目里。

**② 编排规则（关键）**：把 `.workbuddy/memory/MEMORY.md` 的内容**粘贴到项目的「指令」字段**——这是"对 AI 的全局行为规则，项目内所有对话自动继承"，驱动路由裁决 / 复杂度三问 / F1-F5 / 接案评估自动触发。
- 验证：在该项目新建对话，说"接案评估怎么触发"→ 能答出"复杂度三问分流"即生效

**③ 项目内添加技能**：技能要加到**项目**里（不是只全局上传）——**项目 → 添加技能 → 上传**，选中 `skills/` 下的技能文件夹（或对应 zip）逐个添加。在项目的「技能」列表确认**8 个随包技能**都启用（推理层 3 个——争点/演绎/竞合——不在随包：下载原版后按 [推理层接入指南](../docs/推理层-接入指南.md) 四·B 用 [适配工具](推理层适配工具/README.md) 一键改 description，再一并添加，凑齐 11 个）。

**④ 固定文件目录（关键，实测必需）**：把 `MEMORY.md` 复制为**用户级 `~/.workbuddy/MEMORY.md`**（不是项目内），写入固定目录规则（如"法律工作目录为 E:\LegalChain-WorkBuddy，材料放 raw/、知识库读写 wiki/"）——这样**所有对话、无论工作区在哪，都按固定目录操作文件**。新对话默认时间戳目录不固定，必须有这条。

> 💡 技能管理里全局上传的技能是"所有项目可用"，但**项目内添加**才能保证该项目对话自动调用。实测：项目内添加 = 该项目对话能触发；只全局上传 = 不保证项目内触发。**以项目内添加为准。**
> 若项目内无法直接添加，需把技能目录**转成 zip** 再上传（WorkBuddy 按 zip 导入）。

## 阶段 D：MCP 检索

- 引导用户注册**元典开放平台**（open.chineselaw.com，法条/案例检索核心源）
- 按 `mcp.json` 把元典 key 填进配置，或在 WorkBuddy **MCP 界面**添加
- 验证：问一个法条能返回原文 + 条文号（联网搜索内置，无需配置）

## 阶段 E：Obsidian 知识库（推荐）

- 引导用户读 `环境配置/01`，装 Obsidian + 新建 vault
- 帮用户建 **wiki 目录结构**（checklists/concepts/entities/sources/synthesis/sessions + index/log/overview）+ 把 `WORKBUDDY.md` 放进 vault 根
- 说明知识库三招用法（收材料/查知识/健康检查）

## 阶段 F：本地 OCR（可选，较重）

- 引导用户读 `环境配置/02`，**先选档**：
  - **通用档**（默认推荐）：V6 常规识别，~232M 自动下载，依赖轻，日常够用
  - **完整档**（可选增强）：+VL 复验（~2.5G），表格/多栏/低质量扫描件才需要
- **说明**：不装不影响核心 skill；完整档按 [06-VL完整档适配指南](环境配置/06-VL完整档适配指南.md) 引导测试与调整
- 若装：按 02 步骤 → 建虚拟环境装依赖 → 适配路径（改 D:\ai-models 为本机）→ 测试一个 PDF

## 阶段 G：验证

- 引导用户跑 `使用手册.md` 第二章「装完第一步先试 3 个」：
  ① 查法条 ② 案件评估 ③ 文书核查
- 三个都能正常 → **环境搭建完成**
