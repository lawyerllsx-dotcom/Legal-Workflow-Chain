# Legal-Workflow-Chain 工作流使用手册（WorkBuddy 版）

> 写给第一次用的人：这套东西**解决什么问题、怎么用、能帮到你什么**。
> 它是一套给法律工作者的 AI 工作流——把"查法条、理证据、写文书、核事实"这些重复劳动，交给 AI 按规范干，你来审。

---

## 一、这套工作流是干什么的

### 痛点：法律工作里最磨人的不是疑难案件，是重复劳动

- 查一个法条、找类似案例、确认赔偿标准——**每次都要重新查一遍**，查完忘了来源
- 拿到一堆材料，要理成证据目录、提炼争议焦点——**耗时但机械**
- 写律师函、起诉状——**格式和法律依据容易出错**
- 推理到一半，忘了法条哪来的、前提没核验——**结论不可追溯**

### 这套工作流怎么解决：11 个 skill，每个只做一件事

> 随包自带 8 个；推理层 3 个（争点/演绎/竞合）按 [推理层接入指南](../docs/推理层-接入指南.md) 四·B 自取接线后补齐，共 11 个。缺推理层时其余 8 个照常可用。

法律分析被拆成 6 个环节，每环一个 AI 技能，环环交接：

| 环节 | Skill | 帮你做什么 |
|------|-------|-----------|
| ① 接案评估 | **接案评估** | 新案子先整体评估：能不能打、什么路径、有什么风险 → 出《案件评估报告》 |
| ② 证据整理 | **evidence-catalog** | 一堆材料 → 结构化证据目录（证明对象/来源） |
| ③ 检索 | **legal-research** | 查法条、查案例、查赔偿标准 → 返回法条原文+条文号（可溯源） |
| ④ 推理 | **deductive-reasoning** / **conflict-resolution** | 案件逻辑三段论分析；法条竞合/证据矛盾裁决 |
| ⑤ 核查 | **legal-fact-checker** | 检查文书/结论的事实是否准确，防编造 |
| ⑥ 输出 | **legal-citation** / **docx-editing** | 引注规范化、Word 文档保留格式编辑 |

**核心承诺**：案号、法条编号、当事人、金额——这些**零容忍项** AI 必须精确核验，不确定就标 `[待核实]`，**绝不编造**。每份产出都视为草稿，由执业律师复核后使用。

### 你和 AI 的分工

| 你负责 | AI 负责 |
|--------|---------|
| 提供案件材料、最终判断 | 检索、梳理、起草、核验的重复劳动 |
| 把关每一步结论 | 每一步带"依据 + 置信度 + 待核验项" |
| 决定接不接、怎么打 | 给选项和利弊，不替你拍板 |

### 这套工作流怎么在 WorkBuddy 跑起来

装好后，WorkBuddy 靠两样东西自动驱动，**你不需要手动指定用什么技能**：

- **编排规则**（两条通道，推荐都配）：
  - **项目「指令」字段**（最官方）：新建项目时把规则粘贴进去，**所有任务自动继承**
  - **个人记忆 MEMORY.md**：放 `.workbuddy/memory/`，也会注入上下文
  两者都包含：路由裁决、复杂度三问、F1-F5 监控、接案评估自动触发。
- **11 个 skill**（8 随包 + 3 推理层自取，见上文说明）：按 description 自动匹配触发。

实际体验：你说一句"帮我评估这个案子"→ 接案评估自动触发 → 出报告 → 按规则分流 → 技能接力 → 拿到完整分析。全程不用告诉它"用哪个技能"。

## 二、装完第一步：先试这 3 个（不用准备任何案件材料）

装好 skill、配好模型后，在 WorkBuddy 对话框依次试：

**① 试法条检索**
```
查一下《民法典》第 585 条违约金的规定，以及司法实践里违约金上限一般怎么掌握
```
→ 预期：legal-research 触发，返回法条原文 + 条文号 + 相关解释。

**② 试案件评估**
```
帮我评估一个买卖合同纠纷：甲卖给乙一批货，货到了乙没付钱，货款 9 万，有一个保证人，合同约定违约金日万分之五，看看能不能起诉
```
→ 预期：接案评估触发，出《案件评估报告》（当事人/标的/法律定性/风险/打法选项）。

**③ 试文书核查**
```
检查这段话有没有问题："根据合同法第 60 条，乙方应支付货款 98000 元"
```
→ 预期：legal-fact-checker 触发，指出"合同法"应为民法典、《民法典》第 626 条，金额待核实。

三个都能正常出活，说明环境 OK。

## 三、真实场景演示：一个案子怎么走完全程

> 以下为**脱敏示例**（虚构案情）。它展示一个复杂案子从接到写完的完整链路。

**场景**：当事人拿来一份欠款材料，说对方公司拖欠货款，还有一个个人担保，问能不能告、怎么告。

### 第 1 步：接案评估（入口）

你说：`帮我评估这个案子，材料在这里（提供材料）`

AI 产出《案件评估报告》：
- 当事人：原告 = 你方公司；被告 = 某贸易公司（债务人）+ 张某（保证人）
- 标的：货款 320,000 元 + 违约金
- 法律定性：买卖合同纠纷，主债务 + 连带保证（需核保证条款）
- 有利：有送货单 + 对账单；不利：保证方式要核（一般还是连带）
- 风险：时效 / 保证期间 / 违约金标准
- 打法：先发律师函催告 → 谈判 → 起诉
- **复杂度建议：五层深链**（多被告 + 违约金竞合）

### 第 2 步：AI 自动接力（深链）

接案评估输出接力标记，按复杂度三问自动分流进深链：

```
[Skill接力: dispute-issue-identification]
```

- **争点识别**：列出 4 个核心争点（C1 货款 / C2 违约金标准 / C3 保证责任 / C4 是否夫妻共同债务）
- **法条检索**：查《民法典》584/585/626/688 条 + 买卖合同解释 + 民间借贷解释——返回法条原文
- **演绎推理**：对 C2 做三段论——合同约定日万分之五 vs 年利率上限 vs LPR 四倍，哪个适用
- **竞合裁决**：确认违约金约定有效但受司法保护上限约束，附类案支撑（案号 + 裁判规则）
- **事实核查**：核验金额 320,000、当事人身份、法条原文——无 `[待核实]` 残留
- **引注**：所有法条按规范格式补全

### 第 3 步：你拿到什么

一份**可复核的完整分析**：从评估报告到推理链，每一步都有依据、可追溯。你只需要：审一遍 → 补你掌握的事实 → 决定下一步。

> 这就是这套工作流的核心价值：**复杂案件不散**。检索来源不丢、推理步骤对得上、结论能核验。

## 四、三档深度详细用法

系统会自动判断走哪档（由接案评估的复杂度三问决定），你也可以直接说。

### 档 1：单个 skill——最快，一个提问一件事

| 你想 | 你说 | AI 给你 |
|------|------|---------|
| 查法条 | "民法典 585 条违约金怎么规定" | 法条原文 + 条文号 + 相关解释 |
| 查赔偿标准 | "人身损害误工费怎么算" | 计算标准 + 依据法条 |
| 判断合法性 | "公司不签劳动合同违法吗" | 法条依据 + 责任分析 |
| 整理证据 | "把这些材料理成证据目录" | 结构化证据目录 |
| 写律师函 | "起草律师函，对方欠 32,000 元" | 律师函初稿 + 待核实项 |
| 核文书法条 | "检查这段引用的法条" | 错误标注 + 正确条文 |
| 分析争点 | "这个案子的争点是什么" | 争议焦点清单 |

### 档 2：浅链——2-3 步，一个小分析

**示例**："这个案子我要不要先保全？对方好像有转移财产的风险。"

AI 会：
1. **争点识别** → 货款 + 财产保全必要性
2. **法条检索** → 诉前保全条件（《民事诉讼法》第 104 条）、担保要求
3. **事实核查** → 申请材料清单（保全申请书/担保/财产线索）

你得到：**保全可行性 + 材料清单 + 待核验项**（对方财产线索需确认）。

### 档 3：深链——复杂案件，完整接力

**示例**："这个买卖合同纠纷，货送了钱没收到，还有 3 个保证人，违约金写了日万分之五，帮我看看能不能打。"

AI 走完整五层（见第三节演示），你得到：**接案评估报告 → 争点清单 → 法条依据 → 三段论推理 → 竞合裁决 → 事实核查 → 引注**——一份完整可核验的分析。

**关键区别**：档 1 不接力、档 2 走 2-3 步、档 3 走完整链——由复杂度三问自动判断，不用你手动指定。

## 五、每个 skill 详解（什么时候用 / 给什么 / 得什么）

### 接案评估（入口）
- **什么时候**：评估新案子、接案前、风险预判、"能不能打"
- **给它**：案件材料（起诉状/合同/证据/口头案情）
- **得到**：《案件评估报告》——当事人/标的/法律定性/证据盘点/有利不利/风险/打法选项（含调解等非诉路径）
- **注意**：它**不拍板接不接**——给材料给建议，决策在你

### evidence-catalog-generator（证据整理）
- **什么时候**：手上一堆材料要理成目录
- **给它**：证据文件/材料清单
- **得到**：结构化证据目录（每组证据：名称/来源/证明对象/证明力）
- **注意**：证明对象只写基本事实，不写法律结论

### dispute-issue-identification（争点识别）
- **什么时候**：材料有了，但说不清争什么
- **给它**：案件事实/材料
- **得到**：争议焦点清单（核心/次级/背景），区分事实争议 vs 法律争议

### legal-research（法条检索）
- **什么时候**：查法条、查案例、查赔偿/责任标准、"根据什么法律"
- **给它**：法律问题 + 案情
- **得到**：法条原文 + 条文号 + 效力层级 + 相关案例（可溯源）
- **注意**：必须元典/tavily 接通；AI 不会凭记忆编法条

### deductive-reasoning（演绎推理）
- **什么时候**：把事实和法条组织成严密推理链
- **给它**：已确认的事实 + 已核验的法条
- **得到**：三段论链条（大前提-小前提-结论）+ 有效性验证（指出推理谬误）
- **注意**：大前提法条必须已核验，不能凭记忆

### conflict-resolution（竞合裁决）
- **什么时候**：多个法条都能用/证据矛盾/争点优先级
- **给它**：竞合法条 / 矛盾证据 / 争点清单
- **得到**：适用哪个 + 排除哪个 + 理由 + 置信度 + 类案支撑

### legal-fact-checker（事实核查）
- **什么时候**：写文书前、拿到 AI 产出后、检查结论
- **给它**：待核验的文书/结论
- **得到**：事实核查清单（哪些已核、哪些 `[待核实]`、哪些需补证据）

### legal-citation-comprehensive（引注）
- **什么时候**：论文/文书要规范脚注
- **给它**：引用的法条/案例 + 来源
- **得到**：符合《法学引注手册》的脚注

### docx-editing（Word 编辑）
- **什么时候**：改已有的 .docx（保留格式、修订追踪）
- **给它**：docx 文件 + 修改要求
- **得到**：改好的文档（格式不崩）

### vision（识图）
- **什么时候**：识别人物/物体/场景/图表（**不是**文字识别）
- **给它**：图片 + 问题
- **得到**：对图片内容的文字描述
- **注意**：文档/票据上的文字走 OCR，不用它

## 六、工作纪律（AI 会自动约束自己）

1. **零容忍项不编造**：案号、法条编号、当事人、金额——必须精确核验，不确定标 `[待核实]`，绝不编造。
2. **依据跟着结论走**：每一步输出带"结论/依据/置信度/待核验/待办"，来源可追溯。
3. **OCR 与识图分离**：文字内容（文档/票据/截图文字）走 OCR；只有识人识物才用 vision。
4. **草稿需复核**：所有 AI 产出是**草稿**，法律判断和责任始终在执业律师。

## 七、预期行为（重要，先看这个）

### 这套工作流怎么驱动（机制真相）

WorkBuddy 是**自主规划型** agent：你说一句话，它自己拆解任务、规划步骤、按需调用能力和数据，执行完交付。**skill 是"方法论工具库"**（模型按需读取 SKILL.md 按步骤做），不是必须手动接力的模块。

- **单 skill 任务**（查法条 / 核文书 / 写律师函）：模型识别意图 → 调用对应 skill → 交付 ✅
- **接案评估（入口）**：触发 → 十步报告 → 按复杂度三问分流 ✅
- **复杂案子深链**：WorkBuddy **自主规划**执行路径（评估 → 争点 → 检索 → 推理 → 核查 → 输出），按需调用 skill + MCP——这是它官方定位的核心能力 ✅（质量取决于所用模型的规划水平）

### 可能出现的偏差（如实）

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 某一步没做（如直接给结论、没先检索）| 模型规划遗漏 | 直接说"先用元典查一下 585 条原文再分析" |
| 没触发 skill，答得像普通聊天 | 描述匹配失败 | 手动 `/skill名` 触发，或说"用法条检索查…" |
| 多步分析跳步 | 模型为省 token 简化 | 拆开问：一次给一个环节的任务 |

### 两个好习惯

1. **复杂案子可以拆开问**：评估 → 争点 → 检索 → 核查分步，每步给材料，更稳
2. **让 WorkBuddy 存中间产物**：每步结论存进项目目录/指定文件夹，下一步引用

## 八、常见问题

**Q: skill 没触发 / 答非所问？**
先确认该 skill 在「已安装」且**已启用**。提问时描述具体点（给案情、给场景），不要只说模糊的一句话。

**Q: 法条检索不到？**
检查 MCP：元典/tavily 是否配置成功、key 是否填对。没配检索源时，AI 会标 `[待补]` 而不是编造。

**Q: 想自己加 skill？**
一个 skill 一个目录一个 SKILL.md（YAML frontmatter 含 name/description），复制到技能目录即可。触发靠 description，写清楚"什么时候用"。

**Q: 这套和直接问 ChatGPT 有什么不同？**
ChatGPT 是"问一次答一次"；这套是**按法律作业规范走流程**——检索有来源、推理有链条、结论可核验、复杂案件不散。它更慢但更可靠，适合真正要用的法律工作。
