# Wiki 操作规范（WorkBuddy 版）

> 作者实际使用的知识库操作规范（从 CLAUDE.md 的 wiki 约定 + [LLM Wiki 方法论](04-LLM-Wiki方法论.md) 提炼）。
> **目的**：让 WorkBuddy 按此建立和维护 wiki，获得与作者**一致的知识库体验**（结构、命名、链接、三操作、纪律全部对齐）。
> **用法**：建 wiki 时先读本文，按规范执行；放工作目录，配合 Obsidian 使用。

## 一、目录结构

```
<vault 工作目录>/
├── .workbuddy/           # 配置（含 memory/MEMORY.md 编排规则）
├── raw/                  # 原始材料（PDF/文章/案卷），只读不修改
└── wiki/                 # 知识库（LLM 生成和维护）
    ├── index.md          # 索引页（先建，最重要）
    ├── log.md            # 操作日志（追加式）
    ├── overview.md       # 总览
    ├── checklists/       # 实务速查表
    ├── concepts/         # 概念、方法论、术语
    ├── entities/         # 人物、组织、案件
    ├── sources/          # 原始文档摘要
    ├── synthesis/        # 综合分析、跨页面梳理
    └── sessions/         # 会话归档（可选）
```

## 二、页面约定

### 命名
- 小写英文或中文命名，词间用连字符 `-`
- `sources/<来源简称>.md`、`concepts/<概念名>.md`、`entities/<实体名>.md`、`synthesis/<主题>.md`、`checklists/<名称>.md`

### 链接
- 使用 Obsidian Wiki-link：`[[页面名]]` 或 `[[路径/页面名|显示文本]]`
- **默认使用完整路径**：`[[wiki/subdir/页面名]]`，不依赖模糊匹配
- 来源摘要页必须链回 `raw/` 中的原始文件

### 标签
- 概念类 `#concept` `#methodology` / 实体类 `#person` `#organization` `#tool` / 系统类 `#meta` / 速查类 `#checklist`

## 三、三个操作（和作者一致）

### Ingest（摄入）—— 用户说"收进知识库/ingest/处理这个来源"

1. 读 `raw/` 中的原始文档（是图片先读文本，再读关键图片）
2. 向用户汇报关键要点（3-5 点），确认重点方向
3. 写来源摘要页 `wiki/sources/`：元数据（作者/日期/URL）+ 核心论点 + **关键数据标注原文页码** + 链回 raw 文件
4. 更新相关概念页 `wiki/concepts/`、实体页 `wiki/entities/`
5. 完善法条引用（涉及法典 → 建/更法典页，收录引用条文）
6. 更新综合页 `wiki/synthesis/`（新来源强化/挑战已有结论时）
7. 标注矛盾：新来源与已有页面冲突 → 两页都标 `> ⚠️ 矛盾:`
8. 更新 `wiki/index.md` + 追加 `wiki/log.md`

### Query（查询）—— 用户直接提问

1. **第 0 步铁律：先读 `wiki/index.md` 定位相关页面**（在任何检索/搜索之前）
2. 深入阅读相关页；摘要不够再读 `raw/` 原始来源
3. 综合回答：wiki 有的优先引用（`[[页面名]]`）；wiki 不足用外部检索工具补充
4. **判断收纳价值**（满足任一 → 主动询问是否收纳到 `wiki/synthesis/`）：
   - 回答含跨领域/跨页面交叉分析
   - 引用 2 个以上已有页面
   - 含可复用的法律框架/方法论
   - 多轮追问才得出最终结论
5. 收纳后追加 `wiki/log.md`

### Lint（健康检查）—— 用户说"检查知识库/lint"

检查：矛盾（`> ⚠️ 矛盾:` 是否仍存在/可解决）、孤立页面（index 中每页是否有入链）、断链、过期声明、数据缺口、索引一致性（index 覆盖全部实际页面）。输出检查报告。

## 四、核心纪律

1. **Query 先读 index**——防止"wiki 里有却视而不见"（作者踩过坑：跳索引错过关键页）
2. **读到冲突信息标注** `> ⚠️ 矛盾:`
3. **有价值的分析收纳回 synthesis**——不消失进聊天历史（知识复利）
4. **`raw/` 只读不修改**——原始来源不可变
5. **来源摘要关键数据标注页码**——便于回溯（中文学术 PDF 事后难提取页码，摄入时记准）
6. **增量更新不重写**——更新已有页面，而非从头建整个结构
7. 每个页面至少有一个入链（除 overview 外），避免孤立页

## 五、与工作流的配合

- skill 写文书/分析时，可引用 wiki 里的方法论、类案模板（对齐既有知识，不重复造轮子）
- 接案评估产出的报告可收纳成 synthesis 页复用
- wiki 让"明天比今天更厉害"——每做一件事，知识资产跟着涨

> 初始为空没关系——从第一个材料开始，按 Ingest 逐步摄入，慢慢攒。方式和作者一致，体验自然一致。
