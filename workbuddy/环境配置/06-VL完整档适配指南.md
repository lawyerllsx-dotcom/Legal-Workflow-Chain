# 环境配置 · 06 — VL 完整档适配与调整指南

> **给 WorkBuddy 的 AI**：用户选择了完整档（V6 + VL）装 OCR 时，读本文引导。目标：让 VL 复验正常工作、效果达标；出问题能定位排查；效果不满意知道往哪个方向调。
> **原理**：`ocr_contract.py` 内置「V6 常规识别 + VL 复验（低置信行交叉验证 / 低产页自动重试）」两套引擎。VL 模型缺失时自动跳过；**装了 VL 且路径对，复验自动生效**，无需改代码逻辑。

---

## 一、VL 是什么 / 什么时候需要

- **V6**（PP-OCRv6）：常规文档 OCR，快（~2.8s/页），白底印刷体足够
- **VL**（PaddleOCR-VL-1.6）：视觉语言模型，慢（~20s/页），但能读**复杂版式**——表格、多栏、手写、低质量扫描件、图文混排

**VL 复验触发条件**（内置逻辑）：
- C 级页（低置信/低产）→ 必触发
- B 级页 → 仅当 `--verify` 参数且低置信行 > 3 时触发
- 其他 → 不触发（V6 结果够用）

所以：**装好 VL 后，只有遇到复杂版式/低质量页才会被调用**，日常简单文档不受影响。

## 二、模型获取（引擎自动下载，无需手动）

**VL 模型不用手动下载**——`paddleocr_vl_openvino` 引擎在**首次触发 VL 复验时自动从 ModelScope 下载**（`vlm_model_path=None` 时自动 `snapshot_download`），之后缓存复用。

| 项 | 说明 |
|----|------|
| 自动下载源 | ModelScope：`zhaohb/PaddleOCR-VL-1.5-ov`（含 VLM + 布局模型 PP-DoclayoutV3）|
| 触发时机 | 首次遇到 C 级页 / 低置信行 → VL 复验触发 → 自动下载（约 2.5G，耐心等一次）|
| 前提 | 依赖装好（`requirements.txt` 含 `modelscope` + `paddleocr_vl_openvino` 引擎）+ 网络可到 ModelScope + `MODELSCOPE_CACHE` 指向可写目录 |
| 后续 | 缓存复用，不再重下 |

**ocr_contract.py 路径处理**：
- 若 `VLM_MODEL` / `LAYOUT_MODEL` 指向的目录**不存在** → 把它们设为 `None`，让引擎自动下载（推荐）
- 或先让引擎自动下载一次，再把路径指到缓存目录（`MODELSCOPE_CACHE` 下 `zhaohb/PaddleOCR-VL-1.5-ov`）

## 三、路径适配（关键）

打开 `ocr_contract.py`，把作者路径改成你本机的：

| 行 | 变量 | 改成 |
|----|------|------|
| ~23-24 | `PADDLEX_HOME` / `MODELSCOPE_CACHE` 环境变量 | `<你的OCR目录>/.paddlex` / `<你的OCR目录>/.cache/modelscope`（**确保可写**）|
| ~28 | `MODEL_DIR = Path(r'D:\ai-models')` | 你的 OCR 目录 |
| ~29-30 | `VLM_MODEL` / `LAYOUT_MODEL` | **改为 `None`**——让引擎自动从 ModelScope 下载（推荐）；或下载完成后指向缓存路径 |

改完用 `ocr_contract.py --help` 或跑一次普通 OCR 确认脚本不报路径错。

> 关键点：`VLM_MODEL`/`LAYOUT_MODEL` 设为 `None` 后，引擎在首次 VL 复验触发时**自动下载** `zhaohb/PaddleOCR-VL-1.5-ov`（VLM + 布局模型）到 `MODELSCOPE_CACHE`，之后复用。

## 四、验证测试（按顺序，每步确认）

1. **基础不崩**：`ocr 一张普通PDF` → 应走 V6，输出 `.md`，无 VL 报错
2. **VL 能加载**：`ocr --engine vl 一张复杂PDF` → 应出现 `[LOAD] PaddleOCR-VL`，能出结果（慢属正常）
3. **复验触发**：`ocr --verify 一张复杂PDF`（表格/多栏）→ 输出应出现 `[VL] Cross-verifying` 或 `[VL] Low yield → auto-retry` 提示
4. **效果对比**：同一张复杂图，分别 `--engine v6` 和 `--engine vl`，看 VL 结果是否更完整（表格结构、低质量字）
5. **汇总**：`ocr 一张复杂PDF --verify` → 报告含 `VL used: N page(s) cross-verified`

## 五、故障排查表

| 现象 | 原因 | 解法 |
|------|------|------|
| `[VL] Failed: No module named 'paddleocr_vl_openvino'` | VL 引擎没装 | `pip install -r requirements.txt`（含 git+ 那条）|
| `[VL] Failed: ImportError modelscope is required` | modelscope 依赖缺 | `pip install modelscope`（requirements 已含，确认装全）|
| 首次 VL 触发卡在下载 | 自动下载约 2.5G | 正常，耐心等一次；确认网络可到 ModelScope、`MODELSCOPE_CACHE` 可写 |
| 自动下载中断 / 失败 | 大文件网络不稳 | 重试；或手动把 `zhaohb/PaddleOCR-VL-1.5-ov` 下到 `MODELSCOPE_CACHE` 再核对路径 |
| 加载 VL 很慢 / 内存吃紧 | 模型大，CPU 推理 | 正常；只在复杂版式才值得 |
| VL 结果没比 V6 好 | 该页非复杂版式 | 正常——VL 只在复杂版式有价值 |
| 全程没有 `[VL]` 提示 | 复验没触发（没到 C 级/低置信阈值）| 见「效果调整」①|

## 六、效果调整方向（不满意时按需调）

| 目标 | 调法 |
|------|------|
| ① 复验更积极（更多页走 VL）| 加 `--verify` 参数（B 级页低置信>3 也触发）|
| ② 复验更少（省时间）| 不加 `--verify`，只 C 级页触发 |
| ③ 完全回退 V6 纯模式 | `--no-vl-crosscheck` 参数 |
| ④ 换推理设备 | `ocr_contract.py` 里 `vlm_device` / `layout_device` 改 `GPU`（有独显时）|
| ⑤ 调精度 | `layout_precision` 可 `fp16` / `fp32`（`fp32` 更准更慢）|
| ⑥ 提升复杂版式效果 | 确认模型是 1.6（不是 1.5 混用）；给 VL 更完整页面区域 |

> 调整原则：**默认不动**（V6 通用已够）；只有复杂版式质量不达标才按上表微调。

## 七、给 WorkBuddy AI 的引导顺序

1. 读本文 + `02-本地OCR配置.md`，确认用户已选完整档
2. 确认依赖装好（`requirements.txt` 含 `modelscope` + VL 引擎）；**无需手动下载模型**——首次 VL 触发时引擎自动下载
3. 按 06-三 改 `ocr_contract.py`（`VLM_MODEL`/`LAYOUT_MODEL` 设 `None` 自动下载）
4. 按 06-四 跑 5 步验证测试，逐项确认，把结果记给用户
5. 有失败 → 对照 06-五 排查表定位，解决后重测
6. 效果不满意 → 按 06-六 调整方向，试一个看效果再决定
7. 完成后告知：**日常用 V6 默认即可，VL 只在复杂版式自动接管**
