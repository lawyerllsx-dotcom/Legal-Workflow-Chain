# 接案评估

## 定位（2026-08-05 建）

**五层链的接案入口**，不是平行工作流。所有接案/受案分析先经本 skill 评估 → 产出报告 → 按复杂度分流进现有 skill 体系：

```
接案评估 → 报告给上级审
   ├─ 简单/模板化 → ad-hoc 单 skill（本 skill 到此为止）
   ├─ 中等 → 浅链（dispute-issue + legal-research + fact-checker）
   └─ 复杂 → 触发五层深链（本 skill 报告成为深链"开篇摘要"）
```

**身份边界**：本 skill 有**实习/执业两模式**（见「模式开关」），由 CLAUDE.md「接案评估模式」字段或用户明示切换。

## 模式开关（实习 / 执业，2026-08-05）

读取当前模式（优先级：**用户明示 > CLAUDE.md「接案评估模式」字段 > 默认实习**）：

| 项 | 实习模式 | 执业模式 |
|----|---------|---------|
| 报告去向 | 给上级/决策者审 | 自己决策 |
| 接/不接结论 | **不带**（上级拍板）| **带建议**（接 / 不接 / 条件接 + 理由）|
| 附加字段 | 「向上级请教的问题」清单 | 「接案红线核验」+ 决策依据 |
| 责任 | 把评估材料做完整、做规范 | 承担接案决策 |

**共享核心**：十步评估流程 + 报告主体结构 + 运行日志（含「模式」列）。改核心两模式同时受益，两边一起进化——不是两套 skill，是一个 skill 两种视角。

## 不触发情况（强制排除）

| 用户意图 | 应交由 |
|----------|--------|
| 只检索法条/案例 | legal-research |
| 已有完整案情要识别争点 | dispute-issue-identification |
| 写具体文书（起诉状/律师函等）| fact-checker / 文书相关 |
| 格式/引注 | legal-citation-comprehensive |

**判定**：用户说"评估案件/接案/风险预判/能不能打"且给了案件材料 → 本 skill；只是"查/写/改" → 不触发。

## 工作流程（十步，整合现有 skill，不重复分析）

> 每步对接现有能力，报告字段复用，**不在本 skill 内重复做法条检索/争点提取的深挖**——那是下游 skill 的活。

| 步 | 内容 | 对接 |
|----|------|------|
| 1 | **材料阅读**：通读案卷，整理当事人/标的/管辖/时效（**零容忍项**：姓名/金额/案号与源材料一致，不确定标 `[待核验]`）| 直接读材料 |
| 2 | **当事人与利益图谱**：谁 vs 谁，法律关系网络（多被告/担保/债务加入？）| 概览，不深挖 |
| 3 | **事实与法律关系梳理**：时间线 + 核心法律关系定性 | 参考 dispute-issue 逻辑 |
| 4 | **法条支撑检索**：检索核心请求权基础/时效/管辖 | **调 legal-research / 元典**，返回法条原文+条文号 |
| 5 | **路径初步**：诉讼 / 应诉 / **调解协商** 等路径 + 各自利弊 | 概览 |
| 6 | **争议焦点与论证强弱**：列出核心争点，判断我方/对方论证强弱 | 调 dispute-issue 输出争点清单 |
| 7 | **交叉验证与矛盾识别**：事实/证据/法条间矛盾 | 参考 fact-checker 交叉核对逻辑 |
| 8 | **待核实事项与证据缺口**：缺什么证据、什么待核实 | 参考 fact-checker checklist |
| 9 | **有利/不利因素**：分别列出对我方有利与不利的因素（时效/管辖/证据/法律/对方履约能力），不拍胜诉率 | 综合 |
| 10 | **给上级的建议**：打法选项 2-3 条 + 各自代价 + 待核验清单 | 综合 |

## 输出：《案件评估报告》

> 报告对象 = **上级/决策者**。结构固定，方便上级快速决策。

```markdown
# 案件评估报告（{案号/案名}）
一、案件概要：当事人 / 标的 / 管辖 / 时效（零容忍项，未核验标 [待核验]）
二、法律定性：法律关系 + 请求权基础（引用法条编号，来源标注）
三、证据盘点：有 / 缺 / 待核验
四、有利 / 不利因素：
   - 有利：{时效未过 / 证据充分 / 法律明确 / 对方履约能力…}
   - 不利：{管辖劣势 / 证据缺口 / 时效风险 / 对方抗辩…}（不拍胜诉率）
五、主要风险：时效 / 管辖 / 举证 / 执行
六、打法选项（含非诉）：
   - 路径A: {诉讼}（代价：…）
   - 路径B: {应诉/和解}（代价：…）
   - 路径C: {调解/协商}（代价：…）
七、给上级/决策者的建议：{一句话概览} + 待核验项清单
   - 实习模式追加：向上级请教的问题清单
   - 执业模式追加：接/不接/条件接建议 + 理由
八、复杂度建议：{五层深链 / 浅链 / ad-hoc}（理由：…）
```

**不带"接/不接"结论**——由上级在报告基础上决策。

## 运行复盘日志（轻量钩子）

每次跑完评估后，在本 skill 的 `运行日志.md` 记一行（参考 fact-checker 验证记录的轻量模式）：

```
| 日期 | 模式 | 案子类型 | 标的 | 哪里不顺 / 缺什么 | 上级改了什么 |
```

**模式列**确保两模式各自积累反馈；跑 1-2 个真实案子后，据日志同时迭代两模式（由主模型改，非自动）。
